# Repository Guidelines

## Project Structure & Module Organization
`ragbot` is organized by runtime surface:
- `services/api/app/`: FastAPI gateway, agent graph/nodes, auth, retrieval, storage, observability.
- `services/worker/`: ingestion pipeline (`connectors/`, `jobs/`, dedup logic).
- `cli/`: `rag` command-line entrypoint.
- `contracts/`: shared API/tooling contracts (`types.py`, `types.ts`, `openapi.yaml`, `tools.schema.json`).
- `eval/`: evaluation runners and datasets.
- `infra/`: Docker, Helm chart, SQL migrations, and Qdrant init scripts.
- `tests/`: regression/integration tests.

## Build, Test, and Development Commands
- `python -m venv .venv`: create a local environment.
- `pip install -e ".[dev,postgres,qdrant,worker,observability]"`: install the project with all development/runtime extras.
- `cp .env.example .env`: create local configuration; never commit `.env`.
- `uvicorn services.api.app.api:app --reload --host 0.0.0.0 --port 8000`: run API locally with hot reload.
- `python -m pytest -q`: run the complete test suite.
- `python -m pip check`: validate installed dependency consistency.
- `docker compose up -d`: start API + Postgres + Qdrant from the repository root.
- `docker compose --profile ollama up -d`: also start Ollama.
- `docker compose --profile observability up -d`: also start Jaeger.
- `rag ask "Postgres 在系统中的作用"`: quick CLI smoke test after editable installation.

## RAG Correctness Invariants
Treat these as compatibility constraints, not implementation details:
- ingestion and retrieval MUST use the same `Embedder` implementation and vector dimension;
- `QDRANT_DIM` must match the collection and embedding vectors;
- changing embedding model/dimension requires reindexing into a compatible collection;
- chunks and their `Document` record must use the same stable `doc_id`;
- tenant and ACL filters must be applied before evidence reaches synthesis.

## Coding Style & Naming Conventions
Use Python 3.10+ with 4-space indentation, explicit type hints, and small focused modules. Follow existing naming:
- files/functions/variables: `snake_case`
- classes: `PascalCase`
- constants/env-backed settings: `UPPER_SNAKE_CASE`

When API or tool payloads change, keep contracts synchronized across `contracts/types.py`, `contracts/types.ts`, `contracts/openapi.yaml`, and `contracts/tools.schema.json` as applicable.

## Testing Guidelines
Tests run via `pytest` and primarily use `unittest.TestCase` patterns. Name tests `test_*` and group behavior by suite class. For agent/retrieval/ingestion changes, add regression coverage and run the complete suite. CI runs on Python 3.10 and 3.12 and also performs `pip check` and `compileall`.

## Commit & Pull Request Guidelines
History mostly follows Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`). Keep commits scoped and imperative, for example:
- `feat: add repo filter to search endpoint`
- `fix: keep ingestion embedding dimension aligned`

PRs should include a concise rationale, test evidence, related issue/task when available, and contract/docs updates for behavior or endpoint changes.

## Security & Configuration Tips
Do not commit secrets, local documents, generated bytecode, or credentials. Configure runtime through `.env`/environment variables and see `docs/CONFIGURATION.md`. Empty `RAGBOT_API_KEYS` disables API-key enforcement and is only suitable for trusted local development.
