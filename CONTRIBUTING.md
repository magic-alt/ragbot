# Contributing to Ragbot

## Setup

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,postgres,qdrant,worker,observability]"
cp .env.example .env
```

Do not commit `.env`, local knowledge files, database dumps, generated bytecode, or API keys.

## Before opening a PR

```bash
python -m pip check
python -m compileall -q contracts services cli eval
python -m pytest -q
python scripts/export_openapi.py --output build/openapi.json
docker compose config -q
helm lint infra/helm/ragbot
```

For Node client changes:

```bash
cd packages/node-client
npm install --no-package-lock --ignore-scripts
npm run typecheck
```

For retrieval/ingestion changes, explicitly verify:

- index-time and query-time embeddings use the same model/dimension;
- an embedding model/dimension change has a reindex plan;
- identical content in different documents/tenants is not incorrectly dropped;
- re-ingestion removes stale chunks/vectors only after the new view succeeds;
- Source deletion purges indexed knowledge;
- tenant/ACL filtering remains pre-retrieval/pre-synthesis;
- regression tests cover the failure mode being fixed.

## Contracts and docs

FastAPI/Pydantic is the source of truth for HTTP OpenAPI. Use `/openapi.json` or `scripts/export_openapi.py`; do not hand-maintain an OpenAPI snapshot. Domain/tool changes may require synchronized updates to:

- `contracts/types.py`
- `contracts/types.ts`
- `packages/node-client/src/types.ts`
- `contracts/tools.schema.json`
- `README.md` / `docs/*`

## Database migrations

Add ordered SQL migrations under `infra/migrations/`. CI, Docker Compose, and Helm use `python -m services.api.app.storage.migrations`. Do not modify an already released migration to fix a deployed schema; add a new migration instead.

## Commits

Use focused Conventional Commit-style messages where practical: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. Avoid combining unrelated architectural changes without documenting their interaction.

## Pull requests

Include rationale, externally visible behavior changes, test evidence, migration/reindex implications, and remaining limitations. Storage/embedding changes should make rollback and reindex behavior explicit.
