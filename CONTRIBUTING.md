# Contributing to Ragbot

## Setup

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,postgres,qdrant,worker,observability]"
cp .env.example .env
```

Do not commit `.env`, local knowledge files, database dumps, generated bytecode, or API keys.

## Before opening a PR

```bash
python -m pip check
python -m compileall -q contracts services cli eval
python -m pytest -q
```

For retrieval/ingestion changes, explicitly verify:

- index-time and query-time embeddings use the same model/dimension;
- an embedding model/dimension change has a reindex plan;
- chunk `doc_id` matches its `Document`;
- tenant/ACL filtering remains pre-retrieval/pre-synthesis;
- regression tests cover the failure mode being fixed.

## Contracts and docs

Behavioral API changes may require synchronized updates to:

- `contracts/types.py`
- `contracts/types.ts`
- `contracts/openapi.yaml`
- `contracts/tools.schema.json`
- `README.md` / `docs/CONFIGURATION.md`

## Commits

Use focused Conventional Commit-style messages where practical: `feat:`, `fix:`, `docs:`, `test:`, `chore:`. Avoid combining unrelated architectural refactors with a configuration or bug-fix PR.

## Pull requests

Include rationale, externally visible behavior changes, test evidence, migration/reindex implications, and any remaining limitations. A PR that changes storage or embedding semantics should make rollback/migration behavior explicit.
